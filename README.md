# 燃气观测一致性与处置工具（离线）

面向市燃气监管中心的**纯前端离线**应用：在无网络环境下，对巡检轨迹、阀井读数、设备台账、
施工清单与整改回执做装载签名、语义对齐、版本化规则核验、告警双路线压缩、证据图回溯与离线处置同步对照；
并针对隧道/管网巡检中“定位跳到数公里外、坐标规则产生大量越界告警，但扫码与照片显示人员仍在指定片区”的问题，
内置**定位可信度评估、多源证据交叉匹配、漂移段切分、区间位置校正、告警降权与人工复核队列**。

技术栈：**React 18 + TypeScript + Vite + IndexedDB + WebWorker**，运行期无后端、无外部 CDN，
全部数据保存在浏览器 IndexedDB（库名 `gas-consistency-db`，v2 含定位可信度对象仓库）。

## 定位漂移处理的两条路线（均落地）

- **风险调整路线（默认，对所有漂移点生效）**：原始 GPS 坐标与原严重度完整保留，仅依据照片/扫码/报修等
  多源证据，对“由定位单独触发”的越界告警调整风险（可校正段降权、不可校正段维持原级），调整依据逐条留痕；
  后续规则换版可整体重算，时间线不被改写。
- **区间位置校正路线（满足明确校验条件才生效）**：当漂移段同时满足 **C1–C4** 四个条件时，把段内点校正为
  片区锚点的“区间位置”用于直观浏览，但**不替换原始坐标**，并完整保留校正依据；不满足条件的范围标记为
  **不可校正**，给出不能校正的时间范围与原因，强制进入人工复核。

## 3. 使用与验证流程

1. 登录后进入 **「装载器与签名」**，点击「装载确定性场景（三阶段样例）」：
   原始记录（含采样/到达时间、可信度）写入 IndexedDB，并对业务字段固化 SHA-256 签名；可点击「重新验签」。
2. 点击「交给 WebWorker 执行核验」（或进入 **「时序核验器」** 点「运行双路线核验与压缩」）：
   Worker 在后台线程完成对齐 → 分版本核验 → A/B 双路线压缩 → 见证边界校验 → 证据图 → 同步报告，产物全部落 IndexedDB。
3. 依次查看：
   - **语义对齐器**：别名映射、bar→kPa / L/s→m³h 单位换算、GCJ02→WGS84 坐标修正、施工包围盒判定；
   - **规则浏览器**：RV-2026.1 与 RV-2026.2 两版规则参数与变更说明（含定位越界规则 R-GEO 的跳变/速度/可信度门限）；
   - **定位可信度与漂移复核**：逐点可信度八类评分因子、漂移段 C1–C4 校正依据与不可校正范围、
     独立疑点/行程异常/报修联动、复核队列的确认/驳回闭环；
   - **压缩事件双路线**：任选事件进入调查页，路线 A 直接读不可变成员关系；
     路线 B 现场解码见证（显示解码耗时、槽位/字典码、边界校验），两页面可交叉跳转；
   - **证据图**：观测→告警→事件→回执、定位证据→漂移段→校正片区/复核的 SVG 证据链，可按事件筛选可达子图；
   - **处置簿**：离线行动全量保留（含 baseVersion 与同步状态），可继续提交批注/签收/关闭/重开；
   - **同步对照器**：双路线载荷体积对比、逐事件 A/B 等价性表、离线补传冲突的本地/远端原值与解决按钮；
   - **自检与验证**：27 项断言一键复算（与 `npm test` 共用 `src/core/selfcheck.ts`，其中 GEO-1～GEO-8 为定位可信度专项）。

## 4. 两条压缩路线（核心设计）

| 维度 | 路线 A：规范化不可变成员—事件关系 | 路线 B：压缩成员见证 |
| --- | --- | --- |
| 存储 | 每个成员一条 `MembershipRecord`（事件 ID、告警 ID、逐成员贡献、版本戳记，`immutable=true`） | 每个事件一个 `CompressedWitness`：设备+连续时间窗槽位（5 分钟粒度）+规则版本编码、内容寻址告警引用、贡献字典码、`witnessHash` |
| 调查 | 直接索引读取，无解码等待 | 查询时 `decodeWitness()` 确定性解码，并强制 `verifyBoundary()` 检查相邻槽位无遗漏成员 |
| 重算 | 规则换版只重算受影响窗口，新事件经 `parentEventId` 挂接旧事件，旧关系永不改写 | 同左；新见证独立哈希，旧见证保留 |
| 体积 | 索引/同步量较大 | 载荷更小（同步对照页给出实际字节与节省比例） |
| 防篡改 | 关系不可变 + 告警内容寻址 ID | 见证体 SHA-256 哈希，篡改引用后槽位解码直接抛错 |

**两条路线对任何聚合事件都还原相同的成员来源、严重度与逐成员贡献**；不存在只含摘要、
无法还原成员的快照（自检 EV-3 强制断言）。

## 5. 内置样例场景（确定性，无随机数）

同日（2026-11-23）三阶段：

- **阶段一 08:00–12:00 网络漂移 × 施工扰动重叠（RV-2026.1）**
  - VW-001 读数 09:15 延迟 25 分钟、10:30 乱序到达；09:15→10:00 出现 45 分钟采样缺口；
  - 施工区 CZ-01（09:00–11:00）内 11:00 回落跳变按施工清单 `suppressKinds=jump` 抑制，
    降级为 info 但**保留为成员、不批量关闭**；区外 PS-002 的 09:30 跳变正常判罚；
  - VW-001 观测状态 `open` 与台账声明 `closed` 持续矛盾，关联缺失上游 ID 的整改回执 RC-001。
- **阶段二 12:00 规则换版 RV-2026.2（局部重算）**
  - 缺测 30→20 分钟、跳变量程比 0.40→0.25 且升 critical、矛盾容忍 10→5 升 critical、逾期宽限 60→30 分钟；
  - 新增告警样例：PS-002 13:00/13:10 跳变（v1=2 → v2=4）、VW-001 13:30 缺测（v1=1 → v2=2）、
    RC-003 回执延迟 40 分钟（v1 不逾期 → v2 逾期）；v2 事件全部带 `parentEventId` 重算链。
- **阶段三 16:00–18:00 离线补传与同步冲突**
  - FS-003 16:00 缺测、16:20/16:40 读数延迟 70 分钟补传（标注 backfilled）；
  - 巡检端 16:40 离线批注、17:10 基于过期 baseVersion 重开监管端已关闭事件；
  - 同步对照器产出 3 项冲突（事件状态、行动版本、回执 RC-001 状态），双方原值均保留。
- **阶段四 14:00–16:05 定位漂移可信度与复核（确定性坐标，与阶段三时间交叠）**
  - GPS 两次跳到数公里外（最远约 16.9 km），5–10 分钟内连续速度 85–105 km/h，越过巡检可达上限 60 km/h；
  - **漂移段一 14:20–14:40（可校正）**：两侧可信锚点同在 PS-A，段内照片 IMG-9001/9002 与扫码 SC-A-07 均在
    PS-A 内，满足 C1–C4，校正为 PS-A 锚点区间位置；3 条定位越界告警由 critical 降权为 minor，原坐标与原级留痕；
  - **漂移段二 15:35–15:45（不可校正）**：段内扫码 SC-C-11 属另一片区 PS-C，并与报修单
    RP-2026-11-23-09 同时段同设备相互印证，C2/C3 不满足，标记不可校正范围（15:40–15:42），2 条告警维持 critical；
  - 三类异常样例齐全：照片落在漂移段外（独立疑点 ×2）、连续速度越上限（行程异常 ×2）、
    跨片区扫码+报修联动（报修联动 ×1）；全部结论进入复核队列（告警 5、漂移段 2、异常 5，共 12 条复核单）。

## 6. 本地开发与验证方式

- 单元/集成测试：`npm test`（Vitest，Node 环境 + fake-indexeddb），共 31 个测试，分布在 4 个文件：
  - `src/core/geo.test.ts`：haversine/速度、多源证据抽取、可信度评分、漂移切分、C1–C4 校正与不可校正范围、
    三类异常、越界告警降权、复核队列证据回溯（9 项）；
  - `src/core/pipeline.test.ts`：对齐换算、版本化核验计数、内容寻址幂等、A/B 等价性（含 R-GEO 事件）、见证篡改检测、同步冲突；
  - `src/core/db.test.ts`：真实 `db.ts`/`repository.ts` 代码在 IndexedDB（v2 新对象仓库）上的落盘/回读/索引/清理；
  - `src/ui/render.test.tsx`：12 个页面组件树 renderToString 冒烟（含定位可信度页）。
- 浏览器内自检：应用「自检与验证」页，27 项断言覆盖漂移与施工、规则换版、离线补传、双路线一致性、证据完整性、
  定位可信度（GEO-1～GEO-8）。
- 类型检查：`npx tsc --noEmit`（已纳入 build）。

### 已实际执行的验证结论

- `npx tsc --noEmit`：**零类型错误**；
- `npm test`：**31/31 通过**（4 个测试文件）；
- `npm run build`：TypeScript 零错误，Vite 产出主包、CSS 与独立 Worker chunk（`verify.worker-*.js`）；
- `vite preview` 静态托管冒烟：`/`、主 JS、Worker 文件均 HTTP 200；
- 应用内自检断言与 Vitest 共用同一实现，定位专项断言 GEO-1～GEO-8 全部通过（漂移切分、C1–C4 校正依据、
  不可校正范围、原坐标保留、三类异常、告警降权原级留痕、复核队列回溯、R-GEO 进入双路线）。

## 7. 目录结构

```
src/
├── core/                  # 纯领域逻辑（Worker 与测试共用，无 React 依赖）
│   ├── types.ts           # 全部领域类型
│   ├── crypto.ts          # 规范化 JSON、SHA-256 内容寻址、FNV-1a
│   ├── scenario.ts        # 确定性三阶段场景生成
│   ├── loader.ts          # 装载器：签名固化与验签
│   ├── aligner.ts         # 语义对齐：别名/单位/坐标/施工范围
│   ├── geo.ts             # 定位可信度：评分/交叉匹配/漂移切分/C1-C4 校正/异常/降权/复核
│   ├── engine.ts          # 五类规则核验（缺测/跳变/矛盾/逾期/定位越界）
│   ├── compression.ts     # 双路线压缩、见证解码、边界校验、重算链
│   ├── evidence.ts        # 证据图构建与子图（含定位证据/漂移段/复核节点）
│   ├── sync.ts            # 路线统计、A/B 等价性、离线冲突对照
│   ├── pipeline.ts        # 核验编排管线（串联定位可信度子系统）
│   ├── verify.worker.ts   # WebWorker 入口
│   ├── repository.ts      # IndexedDB 仓储（含复核队列解决）
│   ├── db.ts              # IndexedDB 建库/索引（v2，含定位对象仓库）
│   ├── selfcheck.ts       # 27 项自检断言（含 GEO-1～GEO-8 定位专项）
│   └── *.test.ts          # Vitest
├── state/                 # React Context：认证与应用状态（含 Worker 客户端）
├── ui/                    # 页面与布局（HashRouter，10 个业务页 + 登录页，含定位可信度与漂移复核页）
├── App.tsx / main.tsx
└── styles.css
```

## 8. 离线与数据说明

- 应用不发起任何网络请求；「远端快照」为 `sync.ts` 中确定性的模拟数据，仅用于离线冲突演示；
- 清空浏览器 IndexedDB 或点击装载器页「清空工作区」即可重置全部数据；
- 所有时间为固定 ISO 字符串（+08:00），场景可完整复现。
